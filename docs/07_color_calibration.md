# 07 — Colour measurement and calibration

> **Current state: there is no measured colour calibration in this repository.**
> `src/config/calibration/color_calibration.json` is a *synthetic placeholder*
> generated by `src/tools/make_synthetic_calibration.py`. Every L*a*b* value the
> software currently produces is derived from it and is therefore **not a
> measurement**. The processor labels these results
> `SYNTHETIC_PLACEHOLDER`, degrades their quality, and the GUI shows the
> calibration status next to the colour tile and on the completion screen.

## 1. Why a TCS3200 needs care

The TCS3200 outputs four square waves whose frequency is proportional to the
light reaching photodiodes behind red, green, blue and clear filters. It says
nothing about CIELAB. Converting its counts into L*a*b* requires:

1. controlled illumination (the values are only meaningful for the light source
   and geometry they were calibrated under),
2. dark and white references measured through the **same** optics,
3. a colorimetric transform fitted from readings of **measured** reference
   patches,
4. documented measurement conditions and their stability during roasting.

Applying a generic RGB→CIELAB conversion to raw TCS3200 counts would be a
fabrication. The code refuses to do it (REQ-COL-004).

## 2. Pipeline implemented in `src/colaromatic/processing/color.py`

```
raw TCS3200 counts (Hz)
  → dark subtraction per channel
  → white-reference normalisation           (raw − dark) / (white − dark)
  → optional clear-channel illumination      ÷ (clear − dark_clear)/(white_clear − dark_clear)
     compensation
  → 3×3 matrix + 3-vector offset             XYZ = M · rgb + b
  → CIE XYZ (D65, Y scaled to 100)
  → CIELAB (D65, 2° observer)
  → ΔE76 against the profile colour target (when one exists)
```

Every step is unit-tested (`src/tests/test_color.py`), including:
`xyz_to_lab(white) = (100, 0, 0)`, a neutral grey staying neutral, the
low-lightness branch, LAB→XYZ round trip, illumination-drift compensation, and
recovery of a known synthetic matrix by the fitting routine.

The clear-channel compensation divides the normalised channels by the
normalised clear channel, which cancels a lamp intensity change of the same
colour temperature. It is an approximation (the clear channel is not exactly
luminance) and its adequacy for this illumination must be checked during
calibration — it can be disabled per record (`illumination_compensation: none`).

## 3. Calibration record (REQ-COL-003)

```jsonc
{
  "calibration_id": "…",              // traceable identity
  "version": 1,
  "method": "white_and_dark_reference_affine_fit",
  "status": "VALIDATED | UNVALIDATED | SYNTHETIC_PLACEHOLDER",
  "illuminant": "D65",
  "illumination_compensation": "clear_channel",
  "white_reference": { "red_hz": …, "green_hz": …, "blue_hz": …, "clear_hz": … },
  "dark_reference":  { "red_hz": …, "green_hz": …, "blue_hz": …, "clear_hz": … },
  "matrix_xyz_from_normalized_rgb": [[…, … , …], …],
  "offset_xyz": [0, 0, 0],
  "residual": { "n_samples": …, "delta_e76_mean": …, "delta_e76_max": …,
                "delta_e76_rmse": …,
                "note": "residuals computed on the calibration set itself" },
  "reference_id": "colour-checker-2026-10-20",
  "measured_at": "2026-10-20T10:00:00+08:00",
  "provenance": "measured references: references.json",
  "notes": "…"
}
```

`residual` is deliberately labelled as an **in-sample** figure. Reporting it as
accuracy would be a claim the data does not support; an independent check
requires held-out patches (§6).

## 4. Measurement procedure (to be executed; PENDING-HW)

1. Mount the sensor at the intended distance and angle. Record: distance (mm),
   angle (deg), illumination (source, colour temperature, current setting),
   shielding (yes/no), window material.
2. Fix the illumination and leave it on long enough to stabilise. Record the
   warm-up time and whether the values drift.
3. Measure the **dark** reference: cover the optics completely; record repeated
   readings (e.g. 20). Keep the mean and the spread.
4. Measure the **white** reference: a diffuse white standard of known reflectance
   placed at the bean plane. Record repeated readings.
5. Measure each **reference patch** (≥ 12 preferred, spread across lightness and
   hue; at least 4 is the hard minimum). Take repeated readings per patch.
6. Obtain the true XYZ of each patch from a **measured** spectrophotometer or
   colorimeter reading under the same illuminant — not from a lookup table used
   blindly.
7. Fill in `references.json` (schema in `src/tools/color_calibrate.py`) with the
   readings and reference XYZ, then run:

   ```bash
   python src/tools/color_calibrate.py references.json -o src/config/calibration/measured.json
   ```

8. Review the per-patch ΔE76 printed by the tool. Discard outliers caused by
   glare or a bad reading, and re-measure rather than deleting data silently.
9. Leave the record `UNVALIDATED` until an independent check (§6) passes, then
   set `"status": "VALIDATED"` and point `src/config/system.json →
   color.calibration_file` at the new record.

Template for `references.json`:

```json
{
  "reference_id": "colour-checker-2026-10-20",
  "measured_at": "2026-10-20T10:00:00+08:00",
  "illuminant": "D65",
  "notes": "LED ring at 30 mm, 90 deg, shielded",
  "white": { "red_hz": 0, "green_hz": 0, "blue_hz": 0, "clear_hz": 0 },
  "dark":  { "red_hz": 0, "green_hz": 0, "blue_hz": 0, "clear_hz": 0 },
  "patches": [
    { "name": "patch-01", "X": 0.0, "Y": 0.0, "Z": 0.0,
      "readings": [{ "red_hz": 0, "green_hz": 0, "blue_hz": 0, "clear_hz": 0 }] }
  ]
}
```

## 5. Optical-stability assessment during roasting (REQ-COL-005)

For each item, record what was done and the measured effect on ΔE:

| Effect | How to test | Pass criterion (to be approved) |
|---|---|---|
| Bean movement / fill level | static card vs rotating drum readings | ΔE spread within the approved tolerance |
| Lamp drift / heating | 30 min run, readings every minute | no monotonic drift beyond tolerance |
| Window fouling | readings before/after a roast | documented cleaning interval |
| Smoke/steam | readings during a roast | flag when scatter degrades the reading |
| Chamber reflections | compare with/without shielding | documented |
| Sensor temperature | log sensor-adjacent temperature | no shift attributable to temperature |

If the TCS3200 cannot meet the agreed repeatability, that is a finding to
document and escalate — **not** a reason to invent numbers. Options to propose
for approval include a different sensor (e.g. a calibrated colour sensor or a
camera-based setup) and a defined sampling procedure (e.g. measuring a cooled
sample of the batch with a bench instrument and recording that separately).

## 6. Independent verification (do not skip)

1. Split the reference patches: fit on one subset, evaluate on the held-out
   subset. Report held-out ΔE.
2. Re-measure a few patches after re-mounting the sensor to expose alignment
   sensitivity.
3. Measure three roasted-bean samples both with the in-situ sensor and with a
   reference instrument; record the differences.
4. Store every record; never overwrite a validated calibration record. Point
   the configuration at a new file and keep the previous one.

## 7. What the software enforces today

| Guard | Behaviour |
|---|---|
| No calibration file | `process()` returns no L*a*b*, status `MISSING`, quality `degraded` |
| Non-validated calibration | values are reported but flagged; quality is `degraded`; completion summary lists the status |
| Automatic control with the `delta_e` input enabled | start is refused unless the profile has a colour target **and** the calibration is `VALIDATED` |
| Saturation | channels near full scale → `degraded` with a saturation note |
| Invalid channels | non-positive or non-finite → `invalid`, no L*a*b* |
| Over-white normalisation | normalised channel > 1.05 → `degraded` with a clipping note |
| Endpoint by colour on an unvalidated calibration | the endpoint triggers as *estimated* and always requires operator confirmation |
